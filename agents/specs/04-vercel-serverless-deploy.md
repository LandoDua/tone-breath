# Vercel Serverless Deployment Architecture

> **Status**: Implemented and working (Production)
> **Date**: 2026-09-11
> **Live**: https://tone-breath.vercel.app

## Current Deployment Model

Tone Breath runs as a **single Vercel project** that deploys both the PWA and the FastAPI backend as **one serverless function**. There is no separate static-file service: the Python function serves the API, the Swagger docs, and the compiled SPA from `app/dist/`.

Request flow:

```
https://tone-breath.vercel.app/*
        │
        ▼
vercel.json route  { "src": "/(.*)", "dest": "api/index.py" }
        │
        ▼
api/index.py  →  from backend.app.main import app
        │
        ▼
FastAPI app (backend/app/main.py)
        ├─ /health, /auth/*, /sessions/*, /emotions/*, /notes/*  → API routers
        ├─ /docs, /redoc, /openapi.json                           → Swagger (built-in)
        └─ /* (SPA catch-all)                                     → serves app/dist/
```

## Key Decision: One function serves everything

Early attempts split static files (via `outputDirectory`) from the Python function. This failed in practice (see learnings doc). A single FastAPI function that serves both the API and the SPA is:

- **Reliable**: proven pattern; `backend/app/main.py` was already designed to serve `app/dist/`.
- **Simple**: one source of truth, one routing rule, no framework-preset conflicts.
- **FastAPI-native**: `/{full_path:path}` catch-all already implemented and tested locally.

**Trade-off**: static assets are served through the Python runtime (no edge/CDN caching of hashed assets). Acceptable for the MVP. If needed later, split static assets to Vercel's CDN via `outputDirectory` while keeping `api/*` as a function.

## Critical Configuration Files

### `vercel.json` (repo root)

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "buildCommand": "cd app && npm install && npm run build",
  "routes": [
    { "src": "/(.*)", "dest": "api/index.py" }
  ]
}
```

- `buildCommand` builds the PWA into `app/dist/` **before** Vercel bundles the Python function, so `app/dist/` is present in the function's filesystem at runtime.
- The single catch-all route sends every request to the Python function.
- **No** `outputDirectory`, **no** `cleanUrls`, **no** framework preset — vanilla "Other" project.

### `api/index.py` (Vercel function entrypoint)

```python
import os
import sys

# Vercel's Python runtime does not guarantee the repo root is on sys.path.
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

from backend.app.main import app

vercel = app
```

The `vercel` variable is the ASGI app Vercel invokes. The `sys.path` guard guarantees `backend.app.main` is importable regardless of the runtime's working directory.

### `requirements.txt` (repo ROOT — location is critical)

Must live at the **root of the Root Directory**. Vercel's Python builder discovers dependencies **only** from the repo root (`requirements.txt`, `pyproject.toml`, or `Pipfile.lock`). Files named `requirements.txt` inside `backend/` or `api/` are **ignored**. If missing, Vercel creates an empty `pyproject.toml`, installs nothing, and every function invocation crashes with `FUNCTION_INVOCATION_FAILED`.

### `backend/app/main.py` — SPA serving (defensive paths)

```python
_DIST_CANDIDATES = (
    Path(__file__).parent.parent.parent / "app" / "dist",  # repo-root layout
    Path.cwd() / "app" / "dist",                          # fallback for runtime cwd
)
DIST_DIR = next((c for c in _DIST_CANDIDATES if (c / "index.html").exists()), None)
```

`DIST_DIR` resolves correctly both locally and inside Vercel's function filesystem. Static mount is registered only when the directory exists.

## Project Layout (as deployed)

```
tone-breath/                 # Vercel Project → Root Directory = "/"
├── vercel.json              # build command + routing
├── requirements.txt         # Python deps (Vercel reads ONLY this root file)
├── api/
│   └── index.py             # Vercel entrypoint (exposes `vercel`)
├── app/                     # Frontend: React + Vite + PWA
│   ├── package.json
│   ├── vite.config.ts
│   └── dist/                # Build output (gitignored, regenerated by buildCommand)
└── backend/
    ├── requirements.txt     # local dev deps (NOT read by Vercel)
    └── app/
        ├── main.py          # FastAPI app + CORS + SPA serving
        ├── config.py        # pydantic-settings (reads .env if present, else defaults)
        └── routers/         # auth.py, sessions.py, emotions.py, notes.py
```

## Vercel Project Settings (must match)

| Setting | Value |
|---------|-------|
| Root Directory | `/` (repo root) |
| Framework Preset | Other (or detection ignored) |
| Production Branch | `master` |
| Build Command | provided by `vercel.json` (do not override in dashboard) |

**Gotcha**: Vercel's framework detection originally set Root Directory to `backend/` because it detected Python from `backend/requirements.txt`. That setting is stored **server-side** and can only be fixed in the dashboard (Vercel → Settings → General → Root Directory). It cannot be overridden from the repo for an existing project.

## API Surface (no `/api` prefix)

FastAPI registers routes at the root of the app. There is **no** `/api/...` prefix — the domain mirrors FastAPI paths directly:

| Method | Path |
|--------|------|
| GET | `/health` |
| POST | `/auth/register`, `/auth/login` |
| GET | `/auth/me` |
| POST/GET | `/sessions/`, GET `/sessions/{id}` |
| POST/GET | `/emotions/`, GET `/emotions/calendar` |
| POST/GET | `/notes/`, GET `/notes/{id}` |
| GET | `/docs`, `/redoc`, `/openapi.json` |

## Local Verification

Reproduce the exact production code path before deploying:

```bash
cd /repo/root
source backend/.venv/bin/activate
python - <<'EOF'
import sys; sys.path.insert(0, '.')
from api.index import vercel
from starlette.testclient import TestClient
c = TestClient(vercel)
assert c.get('/').status_code == 200                       # SPA → index.html
assert c.get('/health').json() == {"status": "ok"}         # API
assert c.get('/docs').status_code == 200                   # Swagger
EOF
```

This imports through `api/index.py` (the real Vercel entrypoint), so it catches import-path and dependency bugs.

## Deploy Workflow

1. Work on `develop`; **merge to `master`** (Vercel production deploys from `master`).
2. Each push triggers `vercel build`:
   - Python runtime (uv) installs deps from **root** `requirements.txt`
   - `cd app && npm install && npm run build` → regenerates `app/dist/`
   - Builds `api/index.py` as a Python serverless function (with `app/dist/` in its filesystem)
3. Verify: `/` returns the PWA, `/health` returns `{"status":"ok"}`, `/docs` renders Swagger.

## Common Failure Modes (map symptoms → cause)

| Symptom | Root cause |
|---------|-----------|
| Build: `ENOENT /vercel/path0/backend/app/package.json` | Root Directory set to `backend/` → fix in dashboard to `/` |
| Elegant Vercel 404 on every URL | Static-output config (`outputDirectory`) not honored → use single-function model (current config) |
| `500 FUNCTION_INVOCATION_FAILED` | No root `requirements.txt` → Vercel installed zero deps → `import fastapi` crashed |
| FastAPI plain "Not Found" (not Vercel 404) | Function ran but `app/dist/` absent → check buildCommand order / DIST_DIR candidates |
